# v0.6.0.0 - Rebuild into Vault Manager

The app is rebuilt from `ObsidianScanner` into Vault Manager, split into a tested core and a new window.

State on 2026-11-02: `VERSION` says 0.6.0.0, the newest tag is `v0.2.0.1`, the rebuild is not committed yet, and the window exists at `src/VaultManager.App`.

## Shipped

### Fixed

- Importing settings for an installed but disabled plugin crashed with `IOException`, because it copied `data.json` onto itself.
- A damaged `community-plugins.json` read as empty, and the next write wiped the vault's whole enabled list. It is now refused and left untouched.
- The first vault in the list was the copy source, so an old plugin version could spread. The newest copy is now the source, compared as numbers.
- The plugin list showed the version from the first vault it found, which hid differences between vaults.
- Restricted mode was read from `app.json`, where Obsidian does not keep it. See [[Restricted mode read from browser storage]].
- A vault on an unplugged drive vanished without a word. It now stays, marked offline, and changes wait for it.
- An unreadable vault list looked the same as having no vaults.
- Writes went straight into open vaults. They now wait until the vault is closed.
- Plain writes could leave half a file behind on a crash or a dropped drive. All writes are now atomic.
- Every action rebuilt the window state, losing search text and selection.

### Added

- One-line list of what needs attention with an Update all button, a table of all plugins, and a page for each vault.
- Changes run on click. A copy is saved first, Undo survives a restart, and each line reports its own result. See [[Changes]].
- Changes for an open vault or an unplugged drive wait, finish by themselves when they can, and survive a restart. See [[Store]].
- Profiles as plain files with import, export and an editor, a built-in Tech Tea Studio profile, and a check of each vault against a profile. See [[Profiles]].
- New vault from a profile, including its place in Obsidian's vault list.
- Settings sync between vaults, by category, with a three-way compare. Files holding a live key are blocked. See [[Sync]].
- Online check and install from the official catalog, on a click only, with the size shown first. See [[Catalog]].
- Warning when the same plugin version has different files in different vaults, and a mark for plugins not in the catalog.
- SQLite database for the journal, undo, sync history and decisions, kept outside every vault. See [[Store]].
- Basalt theme, Russian and English, `--demo` mode, state gallery, 431 tests. See [[Basalt palette]] and [[Demo Mode]].

### Changed

- Vault search matches anywhere in a name, instead of only at the start of a word.
- The app is one self-contained exe named after Vault Manager.

## Window simplified

The owner found the first full version too complicated, so the window was cut down before any tag. See [[Run on click instead of plan then Apply]].

- No Apply step: actions run on click through the executor.
- Waiting lines persist in SQLite (`pending_changes`, schema version 2) and finish by themselves when their gate opens, checked on a timer. Failed and needs-review lines do not survive a restart.
- The Changes panel appears only when needed, and the log is a one-line strip.
- The home is one list of one-line rows, and the nav is Plugins and Profiles.
- Settings sync opens from a vault page, and profiles show one result per vault.

## Independent review

An independent review of this version showed cases that could go wrong, and the fixes went in before any tag. The cases are pinned in `ReviewFindingsTests` and `ReviewFindingsViewModelTests`, with `RecoveryNeeded` covered only at `TryPutBack`.

- **Undo.** It refuses and drops a line whose target moved on, keeps notes edited and settings changed since the line ran, saves the settings of a removed plugin, and restores sync history. See [[Changes]] and [[Sync]].
- **Updates.** Only build files are replaced. If the old folder cannot go back, the line reports `RecoveryNeeded` and the copies stay on disk.
- **New vaults.** `RegisterVault` does not follow a failed `CreateVault` and needs an existing `.obsidian`. `CreateVault` checks plugin sources first and clears a half-built folder. `AddParts` rolls back on failure. See [[Profiles]].
- **Files from elsewhere.** `SecretScanner` looks inside lists and objects, a manifest field of the wrong type reads as absent, and profiles with null collections or an unsafe id are rejected. See [[Obsidian]].
- **Settings sync.** Plugin settings are off by default in the window.

The suite had 358 tests at this review, and on 2026-11-02 all 358 passed on the Debug net10.0 build of the test assembly. After the window was simplified it has 431, and all 431 passed in a full run.
